# 生成后由用户选择是否进行 AI 校验 — 修改规格

将 `skills/spec-create-harness/SKILL.md` 中 spec 和 plan 生成后的流程从"自动进入 AI 校验循环"改为"生成后先向用户展示，由用户选择是否进行 AI 校验"。

---

## 1. 需求背景

当前工作流中，spec-generator 和 plan-generator 各自完成生成后，**自动且不可跳过地**进入 AI 校验循环（3.2 / 4.2 节），reviewer 审查 → 发现问题 → generator 修补 → 再审查，最多 5 轮。

这种设计在某些场景下并非最优：

| 场景 | 自动校验的问题 |
|------|---------------|
| **简单需求**（如修改变量名、改文案、小范围重构） | 需求本身很明确，spec/plan 一眼可知没问题，但仍需等待 AI 反复审查，增加不必要的耗时和 token 消耗 |
| **用户自己很清楚要什么** | 用户对需求有成熟的理解，不需要 AI 帮忙"捉虫"，更想快速进入执行阶段 |
| **反复修改的迭代场景** | 第 2/3 轮迭代时 spec/plan 已经很成熟，每次仍自动跑 5 轮校验，效率低 |

因此，改为**生成后先展示给用户，由用户决定是否进行 AI 校验**，把选择权交给用户。

## 2. 修改目标

1. **生成后不自动进入 AI 校验**：spec-generator / plan-generator 完成生成报告后，直接进入用户选择界面
2. **用户可选择进行 AI 校验**：保留现有的完整 AI 校验循环能力，用户想用时可以主动选择
3. **通过率不受影响**：默认仍然建议进行 AI 校验（作为选项 1），降低用户因跳过校验而遗漏问题的风险
4. **选项编号和风格统一**：与现有交互风格保持一致

## 3. 修改范围

### 3.1 Step 3（Spec 生成）流程变更

**修改前：**

```
3.1 spec-generator 生成
      ↓
3.2 AI 校验循环（自动执行，最多 5 轮）
      ↓
3.3 用户确认
```

**修改后：**

```
3.1 spec-generator 生成
      ↓
3.2 用户选择（新增/替代原本的 3.2 + 3.3）
      → 选项 1：AI 校验（进入 3.3 AI 校验循环）
      → 选项 2：直接确认（跳过校验，进入 Step 4）
      → 选项 3：重新生成（回到 3.1）
      → 选项 4：补充信息
      → 选项 5：手动修改
      ↓
3.3 AI 校验循环（仅在用户选择"AI 校验"时进入）
      ↓
3.4 校验后的用户确认（AI 校验完成后回到选择界面）
```

### 3.2 Step 4（Plan 生成）流程变更

**修改前：**

```
4.1 plan-generator 生成
      ↓
4.2 AI 校验循环（自动执行，最多 5 轮）
      ↓
4.3 用户确认
```

**修改后：**

```
4.1 plan-generator 生成
      ↓
4.2 用户选择（新增/替代原本的 4.2 + 4.3）
      → 选项 1：AI 校验（进入 4.3 AI 校验循环）
      → 选项 2：直接确认（跳过校验，进入 4.4 写入状态）
      → 选项 3：重新生成（回到 4.1）
      → 选项 4：补充信息
      → 选项 5：手动修改
      ↓
4.3 AI 校验循环（仅在用户选择"AI 校验"时进入）
      ↓
4.4 校验后的用户确认 → 写入状态
```

### 3.3 状态流转变更

**修改前：**
```
initialized → spec_reviewing → spec_confirming → plan_reviewing → plan_confirming → executing → acceptance → accepted → completed
```

**修改后：**
```
initialized → spec_pending → [spec_reviewing] → spec_confirming → plan_pending → [plan_reviewing] → plan_confirming → executing → acceptance → accepted → completed
```

新增状态：
- `spec_pending`：spec 已生成，等待用户选择（是否进行 AI 校验）
- `plan_pending`：plan 已生成，等待用户选择（是否进行 AI 校验）

`spec_reviewing` 和 `plan_reviewing` 保留，但仅当用户选择"AI 校验"时才进入。

## 4. 用户选择界面设计

### 4.1 Spec 生成后（新 §3.2）

```
spec 生成完成 ✅
路径：.harness/temp/{vId}/spec.md
概要：[2-3 句话总结 spec 核心内容]
主要涉及文件：file1, file2, ...

请选择下一步：

> 1. AI 校验（推荐）— 由 AI 审查 spec 完整性和质量，发现问题时自动修补
> 2. 直接确认 — 跳过 AI 校验，直接进入 plan 生成阶段
> 3. 重新生成 — 丢弃当前版本，重新生成 spec
> 4. 补充信息 — 提供更多需求信息后重新生成
> 5. 手动修改 — 自行编辑 spec.md 文件
```

### 4.2 Plan 生成后（新 §4.2）

```
plan 生成完成 ✅
路径：.harness/temp/{vId}/plan.md
步骤数：N 个步骤
允许文件路径：[file1, dir2/, ...]
概要：[各步骤名称简述]

请选择下一步：

> 1. AI 校验（推荐）— 由 AI 审查 plan 的步骤划分、文件覆盖和依赖关系，发现问题时自动修补
> 2. 直接确认 — 跳过 AI 校验，直接进入执行阶段
> 3. 重新生成 — 丢弃当前版本，重新生成 plan
> 4. 补充信息 — 提供更多信息后重新生成
> 5. 手动修改 — 自行编辑 plan.md 文件
```

### 4.3 各选项对应的行为

| 选项 | 行为 |
|------|------|
| **1. AI 校验** | 进入 AI 校验循环（原 §3.2 / §4.2 的完整流程），完成后回到本选择界面（校验后可继续选择"直接确认"或"重新生成"等） |
| **2. 直接确认** | 跳过 AI 校验，更新 state.json，进入下一阶段（spec → Step 4 plan 生成；plan → Step 5 执行） |
| **3. 重新生成** | 丢弃当前 spec/plan 文件，重新启动 generator Agent 从头生成 |
| **4. 补充信息** | 设置 `waitingFor: "user_supplement"`，提示用户输入补充信息，完成后重新启动 generator Agent（带上补充信息），再次回到本选择界面 |
| **5. 手动修改** | 告知用户可直接编辑对应文件，修改完成后输入"继续"回到本选择界面 |

### 4.4 AI 校验完成后的流程

如果用户选择了"AI 校验"，在 AI 校验循环结束后（无论正常退出还是达到 5 轮上限），**回到 §3.2 / §4.2 的选择界面**，此时选项变为：

```
AI 校验完成 ✅
P0: 0 个  P1: 0 个  P2: 0 个

请选择下一步：

> 1. 直接确认 — 确认通过，进入下一阶段
> 2. 重新生成 — 丢弃当前版本重新生成
> 3. 再次 AI 校验 — 再跑一轮 AI 审查
> 4. 补充信息
> 5. 手动修改
```

> 即：AI 校验完成后将用户带回选择界面，此时"AI 校验"选项自动变为"再次 AI 校验"（第 3 项），新增"直接确认"作为当前推荐操作。

## 5. 与现有功能的兼容

| 现有功能 | 是否受影响 | 说明 |
|---------|-----------|------|
| AI 校验循环（3.2 / 4.2） | 保留 | 内容不变，只是改为用户主动选择后才进入 |
| 最多 5 轮限制 | 保留 | AI 校验循环内部保持不变 |
| 用户确认界面 | 精简 | "重新生成"和"再次 AI 校验"已前置到选择界面，确认界面只保留"继续" |
| 补充信息 | 保留 | 逻辑不变，入口从确认界面移到选择界面 |
| 手动修改 | 保留 | 逻辑不变，入口从确认界面移到选择界面 |
| 中断恢复 | 需更新 | 新增 `spec_pending` / `plan_pending` 状态的恢复逻辑 |
| 状态文件 | 需更新 | 新增两个 `status` 值及对应更新时机 |

### 5.1 中断恢复逻辑更新

在中断恢复机制中，增加对新增状态的处理：

```
- `spec_pending` → 从新 §3.2 用户选择界面继续（展示 spec 概要，让用户重新选择）
- `plan_pending` → 从新 §4.2 用户选择界面继续（展示 plan 概要，让用户重新选择）
```

## 6. 不涉及的变更

- 不修改 AI 校验循环内部的审查逻辑和标准
- 不修改 references/review-spec.md、review-plan.md 等参考文件
- 不修改 Execution Agent 的执行流程
- 不修改 Step 5（执行与测试）的逻辑

## 7. 验收标准

1. **spec 生成后不自动进入 AI 校验**：generator 完成报告后，展示 §4.1 的选择界面，等待用户选择
2. **plan 生成后不自动进入 AI 校验**：generator 完成报告后，展示 §4.2 的选择界面，等待用户选择
3. **AI 校验可主动选择**：用户选择"AI 校验"后，进入完整的 AI 校验循环（与原流程一致）
4. **可直接跳过**：用户选择"直接确认"后，跳过 AI 校验，进入下一阶段
5. **AI 校验后回到选择界面**：校验完成后让用户重新选择（确认/再校验/重新生成等）
6. **状态流转正确**：新增 `spec_pending` 和 `plan_pending` 状态在正确的时机写入
7. **中断恢复支持**：从 `spec_pending` / `plan_pending` 状态恢复时，回到对应的选择界面
8. **原 AI 校验循环不受影响**：用户主动选择后，校验循环的行为和上限与之前完全一致
