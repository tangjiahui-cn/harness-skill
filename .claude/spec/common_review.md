# P0/P1/P2 通用评审框架

基于分级的结构化评审方法论，适用于各类文档和产物的审查。

## 核心理念

1. **分级优先** — 按 P0 > P1 > P2 分级，默认只输出 P0 + P1
2. **范围锁定** — 只审查本次产物，不翻旧账（除非相邻内容暴露了严重问题且修复成本极低）
3. **务实导向** — 考虑修改成本和收益，不追求理论完美

## 分级体系

### 🔴 P0 — 阻塞级（必须修改）

| 类别 | 描述 |
|------|------|
| 内容遗漏 | 关键内容缺失导致下游无法正常推进 |
| 逻辑矛盾 | 同一产物中存在相互冲突的描述或要求 |
| 方案缺陷 | 选型或设计存在明显问题，会导致后续工作走错方向 |
| 不可验证 | 标准模糊、缺失，导致无法判断产物是否合格 |

### 🟡 P1 — 建议级（建议修改）

| 类别 | 描述 |
|------|------|
| 描述不清 | 表述含糊、歧义，可能引起误解 |
| 边界缺失 | 边界条件、异常场景未被覆盖 |
| 上下文断裂 | 内容依赖外部上下文但不做说明，读者无法理解 |
| 不完整 | 有改进空间，但当前版本尚可工作 |

### 🟢 P2 — 可选级（默认不输出）

| 类别 | 描述 |
|------|------|
| 措辞润色 | 表述可更精炼或清晰，但不影响理解 |
| 格式风格 | 排版、标记风格不一致 |
| 过度设计 | 为不确定的未来做的提前扩展 |

## 通用审查原则

| 原则 | 说明 |
|------|------|
| **范围锁定** | 只审查本次产物的内容。不要质疑产物本身的定位和范围（那是需求阶段的事），只检查产物内的一致性、完整性、可行性 |
| **务实导向** | P0 必须提；P1 选择性提（同类问题出现 3 次以上才提炼为共性问题）；P2 默认不提 |
| **对事不对人** | 语气专业平和，聚焦产物本身的问题，不要用指责性语言 |
| **有据可依** | 每条问题必须有明确依据（内容引用、逻辑推论），不接受"感觉不对" |

## 输出格式

### 完整报告模板（AI 校验循环用）

```markdown
## 审查结果

### 🔴 P0（N 个）
#序号 [类别] 标题
- **位置**: 章节/段落引用
- **问题**: 具体问题描述
- **依据**: 引用原文或逻辑推论
- **建议**: 具体修改方案

### 🟡 P1（N 个）
#序号 [类别] 标题
- **位置**: 章节/段落引用
- **问题**: 具体问题描述
- **建议**: 具体修改方案

### 🟢 P2（N 个）
#序号 [类别] 标题
- **位置**: 章节/段落引用
- **问题**: 具体问题描述
```

### 精简版（快速判断用）

当只需判断"是否有实质性问题"时：

```markdown
P0: N 个
P1: N 个
P2: N 个

P0 列表：
1. [类别] 标题 — 位置

P1 列表：
1. [类别] 标题 — 位置
```

## 判断标准：父 Agent 何时进入修补循环

| 审查结果 | 父 Agent 决策 |
|----------|--------------|
| 有 P0 | 必须进入修补循环 |
| 仅有 P1，无 P0 | 建议进入修补循环，但可人工判断是否跳过 |
| 仅有 P2 或无问题 | 直接退出校验循环 |

> 本框架定义通用审查规则。各 skill/spec 在使用时应在此框架基础上，补充领域特定的审查 criteria（即每级类别下具体要查什么）。
